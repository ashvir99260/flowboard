# API instructions

Read the [root instructions](../../AGENTS.md), [backend guide](../../docs/BACKEND_GUIDELINES.md), [naming](../../docs/NAMING_CONVENTIONS.md) and current task.

- Use NestJS with the existing Express `createApplication` factory for runtime and spec export. Features live in `src/modules/<feature>/`; auth/platform remain flat. Group DTOs by feature and request/response role.
- Use `<feature>.request.dto.ts` and `<feature>.response.dto.ts`; every DTO file ends in `.dto.ts` and classes use PascalCase `...Dto`. New suites use `<subject>.unit.spec.mjs` or `<subject>.integration.spec.mjs`; bootstrap suites retain `.test.mjs`. See [exact file patterns](../../docs/NAMING_CONVENTIONS.md#exact-file-patterns) and [retained test exceptions](../../docs/BACKEND_GUIDELINES.md#test-file-rules).
- Follow [creating an API feature](../../docs/BACKEND_GUIDELINES.md#creating-an-api-feature): own controllers/providers in its module, import/export dependencies deliberately, register through AppModule and preserve the shared runtime/spec-only factory. Do not create a default folder per class or a new module per table.
- `core/config` owns reusable settings, `core/utils` pure helpers, and `core/common` HTTP infrastructure/tokens. `shared` owns reusable Nest providers. Core cannot import shared/features; shared cannot import features. Lint enforces those directions; DI ownership/cycle review is still required.
- Controllers own transport and decorators; services orchestrate use cases; database owns Prisma/SQL and scoped transactions. Use central auth, permissions, validation, serialization and error handling once. No second bootstrap or duplicate policy.
- Follow the [endpoint contract checklist](../../docs/BACKEND_GUIDELINES.md#dtos-swagger-and-generated-clients) and [API catalog](../../docs/API_CATALOG.md): schema-derived DTOs, explicit operationId/guard metadata, typed responses, titles/descriptions/examples and generated spec/client checks. Update the spec-only path inventory and OpenAPI response-schema assertions when endpoints change. Do not serialize raw persistence entities.
- Use `.ts` extensions for relative imports in API TypeScript source and keep type-only imports explicit. The API compiler rewrites these to `.js` for emitted Node ESM; tests that import compiled output and package runtime exports still use `.js`. Tests use the existing `.mjs` runners and compiled API; colocate feature suites, keep reusable fixture factories in `test/common`, and own/close isolated resources.
- Use the injected Pino facade with static semantic names and safe metadata; see [logging](../../docs/LOGGING.md). Never log free-form request/response/driver/error content or credentials.
- Realtime metadata is negotiated per connection and authorized per recipient. Keep legacy payload compatibility and no task/actor/private-destination leakage; see [events](../../docs/api-events.md).
