Add failing fixtures for each convention and schema drift, and prove spec export makes no network/listen attempts without runtime credentials.

Files: `packages/openapi/scripts/{check,lint,document,export}.mjs`, `.spectral.yaml`, package scripts, tests/fixtures, and task/matrix/decision evidence. Do not add another runner or change runtime endpoints.

## Behavioral evidence

The initial isolated tests showed that missing limit parameters and missing page envelopes were accepted by the old Spectral rules. The new rules reject those cases, unbounded limits, missing cursors, optional page information and untyped resource items; existing rules reject duplicate/missing operation IDs, unversioned routes, offset aliases and untyped errors. Review identified an empty composition-schema loophole; page resource items now require concrete object properties, with a regression for `anyOf: [{}]`.

The checker generates into a new directory, validates before byte comparison, and cleans up in all tested success/failure paths. A fixture changes an actual DTO field maximum, while preserving document formatting, to prove drift rejection. A separately labeled test loader produces a newly generated invalid spec to prove lint runs against the new output rather than the committed file. Both failure modes preserve committed files.

Real spec export runs with runtime credentials removed and TCP connect/listen, TLS and fetch blocked. Canary tests prove that outgoing and listening socket attempts trigger the guard. No API runtime client or bootstrap rewrite was needed. The limit rule accepts the current bounded numeric-string schema and an explicitly bounded integer schema; runtime query validation remains unchanged.
