## Work contract

Dispatch committed outbox records through a narrow internal database repository and a runtime-only API module. Validate event identity/tenant/aggregate/version against the persisted envelope. Use a stable event UUID as the BullMQ job ID and only a strict tenant-scoped event reference as job data. Claim work with database-time leases and a fresh fencing token on every claim; stale acknowledgments cannot change a newer claim.

Separate dispatching and queued states from worker processing/delivered states. Redis acceptance never completes an event. Recover expired leases and periodically recheck queued rows so Redis loss and worker failures leave durable retry intent. Quarantine malformed events, use bounded exponential backoff for transient failures, and avoid overlapping polling loops. Do not start timers/connections during OpenAPI export. Activity execution remains P11-02.

Files: contracts job/event schemas and tests; database operational outbox repository, additive enum/constraint migration and real-Postgres tests; API outbox runtime/module/configuration and real Redis/Postgres integration tests; runtime wiring, exact dependency/lockfile and plan/decision/matrix/README documents.

Red cases: strict job payload and envelope mismatches; concurrent claims, expired/same-instance reclaim and stale acknowledgment; rolled-back writes; malformed records not blocking valid ones; Redis down at startup/during enqueue then recovery; stable duplicate jobs, lost acknowledgment after enqueue, historical actors, bounded shutdown and inert spec export.

Gates: focused red/green contracts/repository/real-Redis tests, root build/lint/typecheck/format/test, unchanged OpenAPI/client drift and independent review. Keep this task unchecked until all pass.
