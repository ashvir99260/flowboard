# P34-01 Full-card dragging

State: implementation complete; final verification pending. Requirement: R166.

Both board adapters put the drag attributes on the existing card wrapper. Each card is one focusable group, with the library's keyboard instructions and interactive-child blocking. The separate grip button is removed. Title and Move buttons remain native controls; pending writes disable dragging. Existing column drop targets, move validation and optimistic updates are unchanged.

- `pass`: the new browser regression first failed against the old implementation because cards were not drag groups; this established the missing behavior before the source change.
- `pass`: `node --test apps/web/test/whole-card-drag.test.mjs` exercised both boards against the current source in an isolated Next.js development server with test-only API fixtures. It covers pointer pickup from card padding, cross-list/status drops, one handle per card, title opening/closing, Move via keyboard, drag cancellation/focus restoration and disabled pending dragging.
- `pass`: `pnpm --filter @flowboard/web typecheck`.
- `pass`: scoped ESLint on `BoardCard.tsx` and `WorkspaceTaskCard.tsx`; its first run found existing import-group/hook-spacing violations, corrected with the scoped autofix and verified without remaining errors.
- `pass`: changed-file Prettier check and `git diff --check`.
- `not_run`: full root build, lint, tests, real-service E2E and Docker checks for this revision. Existing board/accessibility/realtime test selectors were updated but their full suites were not rerun.

The focused check verifies task-drawer opening and closing, not loading or editing its form contents. It does not establish touch-device or screen-reader acceptance. No API, authorization or generated contract changes were required.
