# P39-01 — Clarify runtime and deployment targets

Date: 26 October 2026
State: complete
Requirements: R173; clarifies R98/R99 and preserves R147

## Outcome

[D171](../DECISIONS.md#d171--four-explicit-run-and-deployment-modes) and the [run/deploy guide](../RUN_AND_DEPLOY.md) separate four modes: native app development with Docker PostgreSQL/Redis, a full Compose preview without manual environment setup, the temporary Vercel/Neon/Upstash demo, and planned production Docker images in Amazon ECR. Current publication still uses GHCR; ECR integration is P39-02 and unchanged-image promotion remains P00-11/P00-12.

The native-development instructions include one-time API initialization for an empty database before the worker starts. The Compose preview already orders startup through API readiness. No application code, deployment configuration, credentials or live resources changed.

## Review and limitations

An independent read-only review checked the four modes and native startup commands. Its two stale delivery statements were corrected: outbox polling belongs to the worker, and temporary demo acceptance passed in P38-03 while main-branch CD activation remains separate. Existing historical evidence remains unchanged.

P39-02 requires the AWS account, region, repositories and least-privilege IAM/OIDC setup before ECR publication. The container runtime is a separate choice; this task makes neither choice nor a production readiness claim.
