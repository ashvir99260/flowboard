# P32-03 Header actions and invitations

State: implementation complete; final verification pending. Requirement: R163.

New task opens the current list's editor or a visible-list picker. Administrators get Settings and Invite. Invitations use shared schema/RHF controls and generated create/accept operations, keep failed drafts, prevent duplicate submit and report link creation accurately. The acceptance URL stores the secret in its fragment, clears it after success, and requires an explicit acceptance action by the matching signed-in email. No email transport is implemented.

- `pass`: local browser smoke opened the workspace destination picker and chosen task form. Empty invitation submission displayed its email validation and focused the field. The dialog closed without creating an invitation.
- `not_run`: created-link/acceptance, role visibility, error/conflict/dirty-draft automated journeys and root quality gates for this revision.

Added `apps/web/test/invitation-data.test.mjs` and `apps/web/e2e/workspace-actions.spec.ts`. Sign-in from another tab uses a page reload to recreate the invalidated client session before accepting. Full acceptance remains pending; no emails were sent during the smoke review.

The old list-toolbar New task action was removed after the live review exposed duplicate creation controls. The header owns this action for both board levels; the new journey asserts exactly one control on a selected list.
