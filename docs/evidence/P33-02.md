# P33-02 Separate frontend component modules

State: implementation complete; final acceptance verification pending. Requirement: R165.

Split the 24 multi-component web/playground modules into separately named components. Auth, session, notification, realtime and task-editor contexts keep one shared instance in their own context modules; their public hooks now live in `.ts` files. Component state, keys, hook order, form lifetime and callbacks remain unchanged. Shared UI/forms component filenames and every dependent import move atomically with the split.

- `pass`: source comparison confirmed the assigned component bodies were preserved apart from exports/names; relative import/cycle review found no missing paths or value cycles.
- `pass`: `pnpm --filter @flowboard/ui --filter @flowboard/forms build`.
- `pass`: `pnpm --filter @flowboard/web typecheck` after fixing explicit error-result typing and splitting the administration selection discriminant into separate variants. These typing corrections retain the existing runtime behavior.
- `not_run`: full root gates, Storybook browser acceptance and end-to-end regression suite for this revision.

PascalCase file moves and import updates are committed with the component extraction to avoid publishing an intermediate broken module graph. P33-03 records the naming rules and focused enforcement.
