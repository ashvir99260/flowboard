# P21-01 Shared UI modules

Date: 2026-10-25. State: complete. Requirement: R142; preserve R23/R70/R134/R137/R139/R140. Dependency P20-01 is complete.

Scope: D146. Restructure reusable UI into module-owned camelCase files, split distinct component implementations, preserve root exports and behavior, update imports and current guidance/source links. React lint behavior belongs to P21-02.

## Implementation and review

Moved presentation into `src/modules` with camelCase filenames; utilities/hooks have explicit folders. Split independent primitive, layout, board, activity, notification and field-input implementations. Surface/Toolbar keep their cohesive styled slots. The primitive facade and root package exports stay stable; stories remain outside runtime source.

Two independent read-only reviews found no broken relative imports, cycles or public export changes. They checked client/SSR boundaries, toast context identity, focus/cleanup, numeric draft/clear semantics, polymorphic refs and grid/drag geometry. Current source links and naming guidance were updated; historical evidence retains its original revision context.

Two full runs reproduced a missing success notification after dismissing an error. Focused browser reruns passed, but a deterministic component test isolated the cause: Toastify's second queue retained the replacement while the old exit animation was pending. Removing its redundant limit exposed the next message; review then found that Alt+T could still focus the stale exiting element. Resetting the renderer on controlled-message changes removes that stale element. Both assertions failed before their fixes. Flowboard's existing queue, focus restoration and stale-callback protection remain authoritative. No assertion timeouts were widened and temporary browser diagnostics were removed.
