## Work contract

Add setupClient around fresh generated Fetch clients. Store session state per instance in memory; keep the generated singleton untouched. Use the generated refresh/switch/logout SDK through a separate raw client and return Responses through interceptors so generated parsing stays authoritative. Only bearer-protected401 responses may refresh; retain one replay template for a single retry, including mutation bodies and caller cancellation.

Distinguish authority changes from token refresh revisions. Coalesce concurrent refresh, avoid refreshing again for delayed old-token401s, and reject old-session responses/retries after logout or workspace switching. Serialize cookie rotation/switches through origin-scoped Web Locks with non-secret revision notifications for tabs. Fail closed on refresh failure, identity mismatch or unsupported coordination; no tokens in persistent browser storage. Keep browser globals lazy and SSR instances independent; Node fetch has no automatic cookie jar.

Files: handwritten session transport/state/synchronization modules in packages/api-client, public exports/dependencies, real generated-SDK transport tests, docs/decision/evidence. No handwritten endpoint implementation, API schema change or UI yet.
