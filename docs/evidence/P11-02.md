## Work contract

Verify strict job identity against committed outbox state, acquire a separate fenced processing lease, insert status activity idempotently, publish the validated invalidation and mark delivered only after publication. Retry publication when activity already exists. Reject malformed/foreign jobs without corrupting another event. Add current-permission, cursor-only activity reads and a generated-client drawer feed that preserves dirty edits.

Agreed test seams: pure shared contracts; public database repositories against real PostgreSQL; BullMQ processing and Redis publication with real services; authenticated REST through Supertest; the rendered task drawer through the existing browser harness. Follow vertical red/green slices at those seams.

Failure cases: duplicate/stalled jobs, stale processing tokens, insertion-before-publication crash, Redis outage, malformed and foreign references, former-member actors, non-status events, empty/forbidden/foreign feeds, cursor tampering/binding/expiry/watermark/ties, dirty drawer refresh and dependency/shutdown behavior.

Gates: focused red/green slices, root build/lint/typecheck/format/test, regenerated spec/client and drift checks, independent source review and browser feed checks. Keep P11-02 unchecked until complete.

## Acceptance evidence

The first contract, consumer, API and browser slices failed on missing exports, repositories, endpoints and visible activity. Real PostgreSQL checks then proved one immutable activity per event, separate processing leases, rejection of stale acknowledgments, strict workspace/task/list/status relationships, and retry after insertion. A review regression first accepted a contradictory nested move delta; shared event validation now rejects that contradiction before publication. The consumer integration suite also covers former-member actors, non-status events, tied timestamps and a stable pagination watermark.

The worker consumes the real BullMQ queue, validates each job against its stored outbox row, stores activity before publishing and only then completes delivery. A failed publication is retried through a freshly constructed consumer without inserting or changing the existing activity. Duplicate jobs publish once after delivery. Real Redis and PostgreSQL interruption checks exercise readiness and bounded shutdown. Search remains explicitly unimplemented under `TODO(NEXT-01)`.

Authenticated HTTP checks prove the activity endpoint enforces current task permissions, returns 403 for same-workspace denial and 404 for foreign/missing tasks, rejects offset/page alternatives and binds signed cursors to caller, workspace, task and limit. Cursor continuation retains its original expiry and upper watermark. OpenAPI and the generated SDK/query options expose the same contract.

Browser checks cover loading, empty, error, older-page and invalid-cursor recovery states. A real second session changes status while the first session has an unsaved title; the first drawer receives the new activity without resetting its draft. The real-service path also checks the drawer at 320px. Activity timestamps use the viewing browser's locale after client-side data loading; the keyed drawer intentionally owns the persisted ID after task creation. These explain the two advisory React Doctor warnings; its parent-branch comparison reports no errors.

Independent read-only review found no remaining blocker in tenant isolation, permission checks, cursor ordering, consumer fencing, retry semantics or dirty-form handling. The initial full-suite attempt lacked permission to reach its disposable Docker fixtures and failed before database setup. Later runs exposed a stale 42-operation Swagger inventory, missing activity response/path entries and a title-only outbox fixture using different source/destination lists. Updating those inventories and making the fixture describe a valid same-list edit preserved every assertion; all eight documentation checks and all 30 API unit tests then passed. Worker startup tests needed explicit fixture-origin allowlists after the worker began using real dependencies; the default test-process network deny rule remains intact. The first lint pass found a missing fixture blank line, which was corrected without changing behavior.

The real-browser selector now includes the required-field marker on the Status label; its focused end-to-end rerun passes. Playground regressions exposed competing Next development locks. A new behavioral test first failed with two development servers sharing the default output directory. Isolating only the output directory still changed the real app's generated TypeScript declarations, which an additional failing assertion exposed. Development fixtures therefore use disposable source copies under ignored `.ai-local/web-tests`, share the installed dependencies and actual Next configuration, and exclude environment files. Cleanup removes only the owned copy. Both playground suites and the two-server/declaration-preservation regression pass together; production application configuration is unchanged.
