# P42-01 Typed API hook structure

Date: 30 October 2026
State: complete
Requirements: R180; preserve R68 and R164.

## Work contract

Apply the user's request-function/options/result pattern to all 25 authored API hook modules. Export typed async request functions, protect owned query/mutation keys and functions through options types, and declare hook result types. Use the existing generated SDK and preserve cursor pagination, cancellation, session tags, retries, response validation, mutation guards, notifications and cache behavior.

Leaf query hooks keep their current inputs and gain optional typed configuration. Composite readers keep their domain results and use typed endpoint option factories; dynamic `useQueries` maps remain maps rather than calls to hooks in loops. The user explicitly chose native `mutate`/`mutateAsync` and caller migration. Mutation validation, notifications, cache work and guards move into owned lifecycle callbacks; placement keeps its immediate projection. Caller mutation observers cannot replace owned policy or optimistic lifecycle, and observer exceptions must not turn a committed server write into a network failure.

Scope: authored web hooks, small feature-owned request/option helpers, shared mutation typing, focused tests and frontend guidance. Generated sources, transport, API endpoints and dependencies remain unchanged.

## Initial failures and corrections

The structure check failed before hooks declared public options/results. The observer regression failed when an `onSuccess` exception replaced a committed request result; the shared helper now awaits observers and reports sanitized observer failures without replacing the request outcome. The notification factory regression failed before the factory preserved the initiating generation.

Source review caught an invitation token mapping error introduced during request extraction. A regression was observed failing before correcting the request body to `token`; it now passes. The native guard test confirms that only one same-session configuration request proceeds, a separate session remains independent, and completed old-session requests cannot emit notifications after a clear.

## Scope and limitations

Leaf and mutation hooks export request functions. Composite hooks retain their domain-shaped results and reuse four typed request/option modules; dynamic reads remain `useQueries` maps. All nine mutation hooks return native results, and their view callers use mutate/mutateAsync. Request validation, scoped generated keys, lazy bounded pagination, request cancellation, retries, form recovery, optimistic placement and cache invalidation remain in place.

No endpoints, generated files, dependencies, deployment configuration or backend persistence logic changed. Separate API generation and application-image builds are not applicable; root build still checks spec/client drift. The real-service browser suites cover administration, bulk edits, permissions, realtime, search, settings panels, subtasks, task editing and workspace actions. P42-01 is complete; no new feature or deployment is included.
