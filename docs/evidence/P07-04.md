# P07-04 Same-origin browser API transport

Date: 2026-10-24
State: complete

## Work contract

Add one server-only Next route forwarding /api/v1 to a fixed runtime API_INTERNAL_URL plus /v1. Read an explicit WEB_ALLOWED_ORIGINS allowlist at request time; require matching Origin for mutations, retain the API's own checks, and never trust forwarded host/IP headers. Preserve methods, raw bounded bodies, query strings, cancellation, API errors and approved refresh cookies; strip unrelated request/response headers, reject ambiguous paths and upstream redirects, and bypass caches. Keep generated operations as the web API interface; the narrow server proxy is the sole handwritten forwarding exception.

Files: apps/web server proxy, route, tests, environment example and package/Turbo config; exact-file ESLint boundary and tests; client browser-base default; Compose/CI test wiring and optional local Compose parallelism passthrough; shared process-test network preload with an explicit loopback-origin allowlist; decisions, README, matrix and evidence. No domain endpoints or auth policy bypasses.

Test seams: request/response forwarding against a local HTTP upstream; built Next route; a real browser using distinct web/API sites and real generated session SDK calls. Verify build-once runtime target selection, no upstream settings in browser assets, cookie/header/path/origin exclusions, abort/size limits, status/error preservation and refresh/logout behavior.

Deployment choice: retain conservative shared proxy-IP rate limits until a separately authenticated provider IP mechanism exists. This task does not enable trust proxy or forward client IP assertions.
