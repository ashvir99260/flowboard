# P02-03 — Membership, invitations and workspace switching

Date: 24 October 2026. State: complete. Requirements: R30, R32, R34; contributes to R42/R92/R114 and preserves R29/R31/R33/R35.

## Work contract

Implement the nine auth/workspace operations: current identity, workspace/member cursor pages, add/change/remove membership, create/accept invitations and switch workspace. Keep strict Zod contracts, grouped DTOs, operation IDs, spec and generated client aligned. Establish the central PermissionGuard/PermissionService with transaction-time rechecks. Protect the last admin and perform departure cleanup/events atomically. Use the existing schema and tenant transactions; no migration is necessary. D103 records cursor, invitation and lock-order choices.

## Behavioral evidence

- **fail, then pass — missing endpoints:** current-user, collection pages, member administration and invitation flow initially returned 404. The completed HTTP suite passes nine cases against isolated PostgreSQL and Redis in `apps/api/src/modules/workspaces/workspaces.integration.spec.mjs`.
- **pass — identity and access:** safe current-user projection; strict bodies/queries; all nine routes require identity; foreign workspace IDs return 404; members cannot administer membership. Emails are visible only to admins or the same member. A user can be an admin in one workspace and a member in another. Live role changes take effect on the next request.
- **pass — invitations and switching:** only digests persist; wrong-email, absent, expired, reused and existing-member invitations reject without elevation. Acceptance does not switch workspace. Switching verifies matching bearer/cookie user and family plus allowed Origin, rotates within the fixed lifetime, invalidates the old selection and leaves other families intact. Removed selected membership prevents normal member access and refresh, while explicit session-only routes permit recovery.
- **pass — conflict and cursor boundaries:** stale revisions reject; no-op role updates retain the revision; concurrent admin demotions permit only one departure. Cursor tests cover signatures, fixed 15-minute chain expiry, caller/resource/workspace/limit binding and malformed input. HTTP tests cover traversal, tampering, stale configuration, unknown filters and uppercase workspace IDs.
- **fail, then pass — review regressions:** uppercase member removal initially retained the assignee in its event; a switch blocked until expiry initially rotated an expired family. Real-Postgres tests reproduced both. The fixes use canonical member IDs and recheck database time after acquiring the destination lock.
- **pass — six database membership tests:** `packages/database/test/membership.integration.test.mjs` verifies grant/assignment cleanup, retained history, task/config/data revisions, expiry while blocked, full rollback when outbox insertion fails, expired/concurrent invitation acceptance, foreign-key lock ordering and keyset traversal with equal timestamps. An initial fixture tried to update immutable createdAt; it was corrected to insert an already-expired invitation, preserving the audit guard.
- **fail, then pass — generated documentation:** Spectral initially reported a missing global Workspaces tag. Review also found the switch destination field inherited an active-workspace-only description; the new assertion in `packages/openapi/test/documentation.test.mjs` reproduced it. Metadata and generation now pass with all 15 operations (nine new), concrete responses and bearer-plus-cookie AND security for switching.
