# P11-05 Drain realtime work before closing application resources

Date: 2026-10-24
State: complete
Requirements: R32, R70, R72, R76, R90
Commit: This record belongs to the task commit; resolve it through Git history.

Release verification discovered an already-running periodic permission recheck continuing after app.close() returned. The API assertions all passed, but Jest rejected a PostgreSQL import after environment teardown. Clearing the interval stopped future ticks without draining its current promise. This task adds an observable deferred-authentication shutdown regression and drains socket background work before later lifecycle hooks close database pools.

The same verification found a one-shot 320px overflow assertion racing the shell's MUI media-query update. The assertion now polls the identical strict bound; the focused real activity test passed at exactly 320px. No viewport, tolerance or timeout was relaxed. P12-02 documentation changes remain parked until this prerequisite passes.

## Red/green and implementation

The original full run passed all 231 API assertions but the API command exited unsuccessfully because the late recheck tried to load PostgreSQL code after Jest teardown. It also reported the independent immediate-resize assertion. Both failures remain in the local flowboard-p1202-test.log; neither counts as a pass.

The added deferred-authentication regression failed against the original service: the database close callback had already run while the recheck was deliberately paused. Four guard regressions also failed: disconnected sockets were allowed to begin/complete authentication or permission checks. After the fix, all 19 focused realtime/guard tests pass. The full root suite subsequently passed.

Detached handshakes, timer rechecks, Redis subscriptions and event dispatches now have tracked promises. Public subscribe/unsubscribe and worker-event operations preserve their results/errors while participating in the drain. onModuleDestroy marks closing, prevents new work, disconnects clients and awaits the pending set. Redis closes in the later application-shutdown hook. The installed Nest lifecycle invokes destroy hooks before its application-shutdown hooks; auth and workspace pools close in that latter phase. Post-await connection/closing checks prevent another permission read, join or emission. Auth/permission guards also stop a disconnected packet before or after their own awaited reads.

Independent review found no remaining blocker in the promise cleanup, lifecycle ordering, admission checks or regression.
