# P36-02 Date and date-time pickers

State: implementation complete; final acceptance pending. Requirement: R171.

Shared `DateInput` supplies MUI X Community DatePicker/DateTimePicker and Day.js localization to RHF and custom date fields. Calendar dates remain YYYY-MM-DD; due-date drafts remain UTC without Z, preserving existing seconds and milliseconds. The request mapper remains unchanged. Partial/invalid sections remain invalid drafts instead of silently clearing or reverting the date. One labeled clear icon emits null. Nullable custom-field multi-selects likewise retain explicit null clearing; chip removal still produces an empty array.

- `pass`: six date/serialization interaction tests under America/Los_Angeles and Asia/Kolkata, including impossible dates, clearing, incomplete sections, ref/error behavior and millisecond preservation.
- `pass`: five date Storybook browser/a11y stories covering calendar selection, partial input, UTC values and required/disabled states.
- `pass`: forms regression file (12 tests), including datetime preservation and clear-to-null.
- `pass`: focused task-drawer browser checks for UTC editing in UTC, Asia/Kolkata and America/Los_Angeles, including blocking a partially cleared date before an explicit clear.
- `pass`: custom-field browser date/multi-select save and clear test.
- `pass`: UI/forms builds; focused type/lint/format checks.
- `not_run`: full root CI, all browser/E2E suites and Docker checks. Full acceptance stays open.

Browser migration initially exposed a multi-select ordering expectation from native selects; the assertion now follows the retained selection order and still verifies exact IDs. Story typing caught an unsupported test-only query option, which was replaced with an exact-name regex.
