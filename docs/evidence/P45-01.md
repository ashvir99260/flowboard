Preserve request cancellation, bounded cursor paging, schema/identity/version checks, notifications and optimistic cleanup.

## Implementation and failures

Hey API now emits 32 native mutation keys. The web generator emits 49 hooks: 15 queries, seven infinite queries and 27 mutations. It also emits typed option factories and key reexports. Five session transitions and two health probes stay outside ordinary UI hooks. Three simple leaf modules and four manual endpoint helper modules were removed; domain adapters retain validation and grouped keys.

The initial public-export check failed because mutation keys were absent. New binding checks failed before generation existed. Additional fixtures reproduced operation-name suffix and import-name collision problems, plus unexpected sibling output; generation now classifies actual Hey syntax, checks names and companion models/keys, and rejects unexpected output. Native pagination types are derived from Hey rather than duplicated. Missing-input writes leave existing output intact. A view-boundary fixture failed before disallowing generated option factories in components; views may consume hooks and types.

Generated hooks bind the supplied session client and scope, preserve cancellation, and use the common mutation execution policy. Domain request functions call generated mutation functions with the real MutationFunctionContext; they do not create a second mutation record. Logical group keys, command variables, validation, notifications, cache work and optimistic cleanup remain owned by their feature.
