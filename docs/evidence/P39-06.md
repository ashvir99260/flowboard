# P39-06 — Specify selective ECR deployment and unchanged-image promotion

Date: 26 October 2026
State: complete (documentation only)
Requirements: R176; clarifies R94/R95/R99 and D171
Source reviewed: `3e65415`, the current package manifests and release planner.

## Outcome

Recorded D173 and the detailed [promotion contract](../PROMOTION.md). Future ECR deployment selects affected runtime consumers, keeps unselected services at each environment's existing versions and promotes the same selected image digests through dev, QA, stage and production. Configuration-only changes reuse existing images; identical image/configuration state requires no deployment. Candidates remain pinned when newer main commits arrive. Compatibility, partial retries, serialization and rollback are explicit requirements.

Source-backed examples are jobs/database/logger → API and worker, UI/forms/client → web, and contracts → web/API/worker. The worker currently consumes contracts too. API-to-OpenAPI generation is a build-only edge and does not itself select web. Updated architecture/HLD/LLD, operating guides and C30 to keep this policy consistent.

This records a plan, not new deployment automation. Current GHCR publication is already selective; the current Vercel demo still builds the complete project from source when its deployment gate is enabled. P39-02/P00-11/P00-12 remain open for ECR implementation and live promotion proof.
