# P01-04 — Fail-closed tenant repositories

Date: 23 October 2026. Requirements: R14/R31 (repository boundary), R32 (DB-derived identity/role). State: complete.

The database package exposes typed read/write units of work and no raw Prisma client. Each unit checks membership; writes lock the workspace before rechecking it. Read snapshots are read-only and repeatable. Nodes, member lookups and grants inject the verified workspace and accept only their named fields. Expired callback handles reject further operations. D79 records the boundary and its deliberately small initial repository surface.

## Evidence

- **pass — red/green:** the initial foreign-tenant read test failed because the scaffold did not expose the scoped factory. The implemented boundary passes the tenant suite.
- **pass — real PostgreSQL:** 20 tenant tests plus the 43 schema tests pass, using a non-superuser application role for the tenant paths. Cases include missing/forged/inherited context, workspace injection, nested Prisma input, foreign reads/updates/relations/deletes, counts and keyset pages, rollback, role differences across workspaces and expired transaction handles.
- **pass — concurrency:** a member write is observed waiting on the workspace lock. Removing its membership before releasing the lock causes the write to reject without mutation. The lock observer explicitly refreshes PostgreSQL's statistics snapshot; the first harness attempt cached the pre-wait snapshot and was corrected without weakening the assertion.
- **pass — independent review:** review identified a valid uppercase UUID failing page-two parent comparison. The focused regression failed before correction; comparisons now use the resolved canonical parent. The full suite passes without skips.
- **pass — final gates:** root build (13 tasks), lint/typecheck (20 each), full tests (21 Turbo tasks; 232 cases total), formatting and whitespace checks. No suite was skipped.
