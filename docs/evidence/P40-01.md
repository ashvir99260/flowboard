## Initial runs and review

The first focused run passed five cases and exposed a test interaction error: clearing the selected parent filtered the autocomplete to its null option. The test now opens the current selection and waits for valid parent options before inspecting them. A second run passed all three added cases but the pre-existing administration journey exceeded its 60-second timeout during the concurrent root checks. The concurrent root run also timed out in API bootstrap, OpenAPI validation and commit-message checks.

The first serial root run exposed a pre-existing cookie-fixture connection refusal at `flowboard-web.test`. Its browser maps that hostname to IPv6 loopback, while the server binds to `localhost`. The failure reproduced in isolation and passed with `NODE_OPTIONS=--dns-result-order=ipv6first`; the already-failed run was stopped. The final complete root run uses this explicit process-local setting and one workspace at a time. It exits 0 with every browser suite passing. No assertion, timeout, application source, test runner or global setting was changed to obtain the pass.

Independent review checked the final cases and found no remaining actionable issues. Network failure is asserted with its exact user-facing message, and successful recovery is checked again after page reload.
