# P01-03 — Relational schema and migrations

Date: 23 October 2026. Requirements: R14, R31, R50, R112 (persistence portions). State: complete.

Implemented all 15 Prisma models and 135 stored fields, explicit restrictive relations, composite tenant keys, JSONB values, configuration/data/row versions, refresh lineage, scoped status/field storage and durable event tables. The migration adds database CHECKs, the current-family partial index and audit triggers. The package generates its internal ESM client with the PostgreSQL adapter; raw client access is not exported. API and worker images include OpenSSL for Prisma's migration engine.

## Evidence

- **pass — red/green:** an isolated real PostgreSQL database initially returned zero audit columns, failing the expected 30-column assertion. After the migration, the suite passed 42 cases. Final verification passes 43 cases, including the complete 135-column inventory and PostgreSQL priority ordering.
- **pass — constraints:** foreign-tenant parent, list, status, override, grant, assignment and activity links reject. Invalid shapes, enum-backed fields, versions, dates, JSON, digests, owner IDs and lifecycle pairs reject. In-use status deletion and duplicate membership/field identity reject.
- **pass — audit:** all 15 tables start with equal timestamps, reject createdAt changes, stamp raw SQL updates and retain timestamps on reads. Prisma updates use the same trigger.
- **pass — sessions/restart:** consume → insert → link rotation is valid; insert-first/link-first and foreign family/user/workspace references reject. Reapplying migration after PostgreSQL restart preserves records and required indexes. Docker changes its ephemeral published port on restart, so the test harness rediscovers it before reconnecting.
- **pass — review:** independent read-only review found no blocking schema defect; its suggested full-column assertion was added.
- **pass — final gates:** root build (13 tasks), lint/typecheck (20 each), full tests (21 Turbo tasks; 162 existing cases plus 7 contract and 43 database cases), formatting, frozen install and diff whitespace checks. The OpenSSL-enabled five-service Compose build/startup/persistence check passed.

An earlier full root run timed out on the existing frontend's five-second HTTP fetch while Docker was concurrently compiling the web image. No timeout or assertion was weakened. Final gates run after the image build. The first Compose run passed all five-service and persistence checks; the final image check also passed with the explicit OpenSSL dependency.
