## Review and limits

Independent review verified workflow input wiring, Hobby/project/repository checks and the stable-alias origin requirement. Live responses exposed two incorrect early fixtures: Git metadata requires withGitRepoInfo=true, and worker readiness belongs to the production daemon endpoint rather than deployment.services. The final implementation checks web/API builds and a matching, ready, live worker instance separately. A direct CLI upload without Git source still fails the automated Git identity gate as intended.

A Vercel production target is necessary for the daemon; it is the dedicated hobby demo, not the future dev/qa/stage/prod promotion implementation. Automatic Git deployment stays disabled and CI activation still requires its protected credentials/gate. This task verifies the adapter and live response contract, not a GitHub-triggered rollout.
