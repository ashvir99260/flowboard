## Acceptance evidence

The initial defaults, request adapter and task-reader tests failed on their missing modules; the opening, save, create, archive and Markdown browser paths failed on their absent controls before implementation. Pure checks now cover zero/false/null values, required/type/option/title/status errors, omitted versus explicit-clear patches, scoped task identity and matching configuration. Board and table both open the drawer through generated queries. Create/edit/archive and safe Markdown preview pass their focused browser checks.

Review reproduced three regressions before correction: server field errors attempted to focus disabled inputs; an invalid mutation response reset a valid dirty draft; and reloading a newly created task after a conflict lost its identity and returned to an empty create form. Deferred first-error focus, full raw response validation and a retained server identity fix those paths. Each corrected browser regression passes. Same-workspace Back preserves the editor; Close/Escape confirm before discarding, and session scope still owns the editor lifetime.

All six custom-field types save in the browser, and optional values have explicit clear controls. Duplicate submissions retain disabled pending controls and send one request. The drawer fits 320/768/1024/1440px, with focus restoration and reduced-motion checks. The 320px and 1440px screenshots were inspected under `.ai-local/p0904/`.

The complete real-API Playwright fixture passes: login, expected board columns, custom-field save/reload, separate Bob session hiding private/denied lists, and two-user version-conflict recovery. The new fixture initially checked readiness before connections finished opening and expected a normal exit instead of Nest's SIGTERM re-emission. Readiness polling, exact loopback network permissions and graceful-shutdown verification correct both issues. PostgreSQL/Redis setup is shared through the test-only `config-jest` infrastructure export; web tests launch the API process without importing another app.

Final read-only review reproduced one more draft-loss path: a transient background current-user refresh replaced the verified workspace shell and unmounted the editor. The failing browser test now passes: retain the same validated workspace for network/5xx errors, show a retry notice, and preserve edits through recovery. Access/session failures still fail closed. Built-in controls were extracted from form submission logic, and the context opener is stable between unrelated provider renders.

React Doctor found no errors; its score service was unavailable. Five remaining advisories concern the deliberate form-to-drawer dirty/busy callback (three reports), mutation settlement coordination and existing workspace-shell control-flow complexity. The parent owns close/discard decisions; board/table observers restart entire cursor generations on settlement instead of independently invalidating signed pages.
