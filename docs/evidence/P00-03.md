# P00-03 — Minimal runnable application shells

Date: 22 October 2026. Status: complete after the verification below. Commit: the Git commit containing this record.

## Scope and outcome

P00-03 adds real Next.js 16.4.2/React 19.3.1, NestJS 12.2.0 and Node worker entry points, production builds/start commands and shared TypeScript/ESLint/Prettier integration. `tsc-watch` 7.2.1 compiles and restarts the Node apps in development. Next route type generation precedes standalone type checking; app exports expose metadata only.

The web setup page explicitly says product features are unavailable. Nest has no custom endpoints; unmatched requests return the framework's 404. The worker logs that queue processing is unimplemented and exposes only TCP process liveness. P01-02, P08-03 and P11-02 TODOs identify their real successors. No runtime DB/Redis clients, authentication, MUI components, domain routes or fake data were added.

R93 is verified across all workspaces. R08 remains **In progress** because actual BullMQ consumption belongs to P11-02. Applicable gates: G01 scope/traceability, G03 behavioral tests, G04 build/static checks and G05 evidence/review; startup portions of G11 are exercised. Docker/release and domain gates remain future work.

## Failing-first observations and fixes

- Six initial API/worker cases failed because `dist/main.js` did not exist. Their real compiled entry points now satisfy startup and invalid-port assertions.
- The first web probe was blocked by the sandbox's localhost restriction. A permitted run failed before the production build. After building, page assertions passed but shutdown initially failed: this installed Next release deliberately exits 143 after closing the server on SIGTERM. The test now checks that exact behavior; Nest's expected re-emitted SIGTERM is also explicit.
- Independent review identified a half-open TCP shutdown case. The added worker test failed after the 10-second cleanup deadline with SIGKILL. Destroying the liveness socket after ending it made the same test pass in about 33 ms, without force-kill.
- The shared test helper now resolves process completion on `close`, after stdout/stderr drain, preventing diagnostic assertions from racing `exit`.
