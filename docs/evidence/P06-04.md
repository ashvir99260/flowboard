## Regression and audit findings

The six legacy pagination parameters already returned400, but their unrecognized-key issues had an empty root path. The new HTTP cases and a nested unknown-key unit test reproduced this. The shared filter now emits one issue per unknown field with its full path and a fixed message, without echoing values. Strict validation and all access decisions are unchanged.

The new suite parses task pages/details/mutation results and error responses through their shared schemas, verifies in-use ancestor status/field rejection using API-created tasks, and checks all live cards against resolved statuses and fields after accepted/rejected operations. It verifies correctly signed expired/unsupported cursor payloads while keeping access JWTs valid, every legacy/duplicate query path, exact restart ID sets, and per-route forbidden/foreign/archived/unauthenticated behavior. The final added reorder anchor cases use the same central permission policy.

D112 intentionally retains the exact JSON scalar filter representation in the cursor fingerprint. The API catalog now states that explicitly, and a regression distinguishes equivalent default sort settings from a changed scalar representation. No normalization behavior or endpoint shape was changed.

Initial audit fixture cleanup constructed a Supertest request before awaiting a revision lookup; the lookup now completes first. An undefined-global lint issue in the test's signing helper was fixed by using the HMAC API's UTF-8 string key support. Neither required production workarounds.
