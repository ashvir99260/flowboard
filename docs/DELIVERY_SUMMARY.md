# Flowboard requirement and delivery summary

This is the reader-friendly map from the original prompt and subsequent requests to the implementation. It summarizes the [requirement matrix](REQUIREMENTS_MATRIX.md), [task ledger](TASKS.md), [decisions](DECISIONS.md) and [evidence records](evidence/README.md); it does not replace them or turn an unchecked item into completed work.

Implementation snapshot: `3cc62b0` (P19-01), reviewed 25 October 2026. At that snapshot the ledger contains 104 tasks: 98 checked and six open. Of R01–R140, 135 are marked Verified, four In progress and one Planned. H01–H06 separately cover the original documentation harness. P20-01/R141 adds this documentation set after that implementation snapshot.

**What is ready locally:** the multi-tenant API, data model, authentication, hierarchy, permissions, inherited configuration, task board/table/editor, realtime/activity, shared component/form systems and verification tooling. **What is not established:** live provider deployment, first real release publication and identical-artifact promotion through four environments. Search remains explicitly deferred.

## Choices that superseded earlier wording

The subsequent P21 refinement is tracked separately: R142/P21-01 groups UI implementations into camelCase module-owned files; R143/P21-02 adds React readability enforcement. Its evidence lives in [P21-01](evidence/P21-01.md) and [P21-02](evidence/P21-02.md), with the matrix retaining each task's current status.

P22 documents the operating model and new Render/Neon hosting plan: [delivery operations](DELIVERY_OPERATIONS.md), [Redis/BullMQ](REDIS_AND_JOBS.md) and [Render](RENDER.md). It changes documentation only. P22-02/P22-03 own Render implementation/live acceptance; P00-11/P00-12 retain the unimplemented four-environment promotion work.

P23-01/R146 adds the [30-diagram atlas](DIAGRAMS.md): seven chapters with editable Mermaid, rendered SVGs and code/reference links. Its [evidence](evidence/P23-01.md) covers documentation semantics, rendering and navigation; it does not rerun or extend product/runtime acceptance.

P24-01/R147 records and verifies the [setup-free Docker preview](../README.md#preview-with-one-command), including clean configuration defaults, automatic data initialization and the real browser/restart checks. Its [evidence](evidence/P24-01.md) retains the distinction between configuration and runtime acceptance.

P25-01/R148 tracks the [named frontend query hooks](FRONTEND_GUIDELINES.md#data-and-session-flow), separating workspace/activity query setup from views while preserving generated transport and cache policy. Its current implementation and validation state is recorded in [P25-01](evidence/P25-01.md).

P26-01/R149 makes the [file patterns](NAMING_CONVENTIONS.md#exact-file-patterns), [API feature workflow](BACKEND_GUIDELINES.md#creating-an-api-feature) and [UI component workflow](UI_COMPONENT_SYSTEM.md#creating-a-shared-component) explicit. Its [evidence](evidence/P26-01.md) verifies documentation against source and identifies retained naming exceptions; it does not claim a code migration or a new runtime test run.

- The replacement package specification superseded the original `shared`/`tsconfig`/`eslint-config` layout. Database, logger, forms, formatting and release tooling have their own explicit responsibilities.
- Prisma was chosen over TypeORM. Public task/configuration operations use tenant repositories; controllers do not own raw queries.
- Workspace-level custom-field defaults were added to the original space/folder/list scopes. The nearest complete definition still wins.
- The explicit drag-engine choice is `@hello-pangea/dnd`, a maintained react-beautiful-dnd fork, replacing the initial dnd-kit plan and the request for the archived original package.
- The headless/shadcn appearance uses MUI's Emotion `styled()` and composition; it did not introduce Tailwind, Radix or the separate styled-components engine.
- Generic form binding moved to `packages/forms`; presentational UI remains independent from RHF and application data.
- Config changes are admin-only. Visibility grants enable task access, not configuration administration.
- Initial shared preview superseded the earlier production-target CD setup. Vercel's current source build does not satisfy future identical-artifact promotion.
- Package manifest ordering is deliberately preserved; PascalCase is for the appropriate types/components, not every variable or API field.
- Storybook extends the playground; it does not replace production SSR or application E2E verification.

Routine branch, pull, commit, author-email and PR/merge requests are repository operations recorded in Git/GitHub history, not additional product features. The implementation sequence and evidence are inspectable without replaying the chat.
