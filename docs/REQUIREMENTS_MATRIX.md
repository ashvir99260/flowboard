## Reading and maintaining the matrix

- **E — Explicit:** a requirement from the original brief, including its replacement package specification. A referenced decision records the selected option where the brief permits a choice.
- **S — Safeguard:** a concrete acceptance condition derived from the existing plan, decisions, or repository instructions. It protects an explicit requirement; it is not an additional product feature or a claim that the original brief stated that detail.
- **Owner / tasks:** the responsible component and backlog task IDs. The first task is the lead owner; later IDs supply dependencies or acceptance coverage. These are responsibility assignments, not parallel implementation authorization. Follow [TASKS.md](TASKS.md) in order.
- **Evidence required:** observable outcomes to record in the owning task's evidence. Test paths in the backlog are planned locations, not existing executable tests. Negative cases must demonstrate the expected rejection and absence of unintended changes.
- IDs are stable. Add new IDs instead of renumbering existing requirements; record scope changes and affected decisions before changing a requirement.

| Status      | Meaning and evidence needed                                                                                                                                                                                                                                    |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Planned     | Owned by a task with an acceptance approach. No implementation or runtime verification is claimed.                                                                                                                                                             |
| In progress | Some portions are implemented and evidenced, but the row still has named work outstanding. It remains open.                                                                                                                                                    |
| Implemented | The complete behavior or deliverable exists and its change is identified in task evidence, but required verification is incomplete. This is not permission to tick the task complete.                                                                          |
| Verified    | All row-specific evidence and the owning task's applicable gates passed on the identified revision; commands, results, environment, and evidence references are recorded. For documentation, this means structural/content review, not application validation. |

Do not promote a row from document wording, a generated file alone, an unchecked test description, or another row's success. After a relevant change, revalidate affected rows and downgrade stale verification until current evidence exists. A blocker leaves the requirement open. See [quality gates](QUALITY_GATES.md), [development workflow](DEVELOPMENT_WORKFLOW.md), and [evidence guidance](evidence/README.md).
