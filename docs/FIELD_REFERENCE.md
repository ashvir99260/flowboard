# Field types, relationships and validation reference

Status: planned contract and persistence specification, reviewed 23 October 2026. This is the field-level companion to [DATABASE_DESIGN](DATABASE_DESIGN.md), [BACKEND_CONTRACTS](BACKEND_CONTRACTS.md) and [API_CATALOG](API_CATALOG.md). It covers all **135 stored fields across 15 models**, followed by derived/embedded values and request controls. No schema or validation code is claimed as implemented.

## Reading each field

- **D** means a PostgreSQL type, FK, unique index, CHECK or audit trigger. **Z** means shared Zod/request-response validation. **S** means a repository/use-case check inside the required lock/transaction. **UI** is presentation behavior and never replaces server validation.
- A NOT NULL column can have a server default and be omitted from create input. Nullable storage does not automatically make a field writable. Explicit null clears only fields whose command allows clearing; omitted PATCH fields preserve stored values.
- ID = opaque UUID. NAME = trimmed, nonblank 1–120 Unicode code points. EMAIL = trimmed/lowercase valid email up to 254. KEY = `[a-z][a-z0-9_]{0,63}`. COLOR = `#[0-9A-Fa-f]{6}`. INT0 = integer 0–2,147,483,647; INT1 = integer 1–2,147,483,647. No string-to-number/boolean coercion in JSON bodies.
- DATE = real Gregorian date with year 0001–9999, represented exactly as YYYY-MM-DD. PostgreSQL date maps through Prisma Date but is serialized as date-only, without a timezone-induced day shift. UTC timestamps use timestamptz(3) → Date → ISO8601 string; millisecond precision matches JavaScript Date. Versions, not wall-clock values, order edits.
- Every incoming string, including JSON keys/values and option labels, rejects U+0000 and unpaired UTF-16 surrogate code units with a field-path400 before persistence. Valid surrogate pairs/supplementary characters remain allowed. Do not normalize passwords.
- Text limits count Unicode code points consistently in Zod refinements, UI counters and PostgreSQL char_length; byte limits on JSON are separate. Token digests use SHA-256 over server-generated 256-bit random credentials; these are not password hashes.
- Unless a row explicitly says otherwise, scalar fields have no relation. All FKs use RESTRICT/NO ACTION on physical deletion. Archive is the product delete policy. Full resource DTOs expose safe fields; embedded summaries deliberately select fewer fields. Internal columns never become public merely because a generated ORM type contains them.

## Cross-field database checks and transactional rules

- Invitation acceptedAt and acceptedById are both null or both set; D checks pair shape. S checks current time, email match and single-use acceptance.
- RefreshSession.replacedById differs from id and requires usedAt; D checks shape and same-user/family composite FK. S prevents cycles, enforces fixed family expiry and revokes on replay.
- OutboxEvent leaseOwner/leaseUntil are both null or both set; dispatching and processing require the full pair. Expired leases remain valid rows awaiting recovery. delivered iff completedAt is set; other states cannot claim completion. Clear lease fields on queued/delivered/failed/pending transitions. S verifies the lease owner and persists state changes atomically.
- StatusOverride first introduction needs complete display values; D scalar checks alone cannot establish an inherited value. S resolves the final set and checks every affected descendant and in-use task.
- FieldDefinition.options array shape is a D check; valid stable IDs, type-specific options, count bounds and stored task compatibility are Z/S rules.
- Activity FKs establish same-tenant relationships but do not prove the payload belongs to the event. Worker S checks task, actor, event type/version and change values against the persisted event before idempotent insertion.

Negative string fixtures include NUL and lone-surrogate values/keys; a valid emoji proves supplementary characters and code-point limits round-trip.

Migration tests exercise D checks directly. Contract tests exercise Z errors at precise field paths. Real PostgreSQL API/worker tests exercise S checks, races and rollback. A documentation row never proves that its validator or constraint has been implemented.

Reference: PostgreSQL documents [date/timestamp types and fractional precision](https://www.postgresql.org/docs/current/datatype-datetime.html); our millisecond precision and validation bounds are explicit Flowboard choices. Its [JSON rules](https://www.postgresql.org/docs/current/datatype-json.html) explain the NUL/surrogate restrictions.
